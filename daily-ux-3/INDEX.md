## 1. 时间依据（怎么量的）

不能只看「看起来保存了」。每个关键窗口都用**设备内同一条 shell** 取时间戳：

```sh
adb -s emulator-5554 shell 'input text "x"; T1=$(date +%s%3N); input tap 74 147; T2=$(date +%s%3N); echo "T1=$T1 T2=$T2 间隔=$((T2-T1))ms"'
```

- `T1` = 最后一次输入完成后、点返回**之前**的设备时刻；
- `T2` = 返回点击派发完成时刻；
- 应用写入的 `updatedAt`（`files/notes.json`）若落在 `[T1, T2]` 区间内，说明这次落盘由**返回动作**触发（`saveAndLeave()`），而不是 500ms 防抖（那要到 `T1+500` 之后）。

编辑器里的自动保存是 `LaunchedEffect(note.id, title, content) { delay(500); updateNote(...) }`，
返回按钮走 `saveAndLeave()` 里同步的 `updateNote(note.id, title, content)`。本轮测的就是「防抖还没到点就离开」。

| 检查 | 最后输入→返回 | 区间 | `updatedAt` 是否落在区间内 | 触发来源 |
|---|---|---|---|---|
| 新建笔记 | **46 ms** | 1794491402839–1794491402885 | 1794491402874 ✔ | 返回动作 |
| 已有笔记（改标题+删段+追加） | **34 ms** | 1794491471026–1794491471060 | 1794491471050 ✔ | 返回动作 |
| 往返 R1 | **60 ms** | 1794491515590–1794491515650 | 1794491515623 ✔ | 返回动作 |
| 往返 R2 | **60 ms** | 1794491531635–1794491531695 | 1794491531686 ✔ | 返回动作 |
| 往返 R3 | **62 ms** | 1794491536835–1794491536897 | 1794491536889 ✔ | 返回动作 |
| 新笔记首字符后立即返回 | **44 ms** | 1794491714117–1794491714161 | 1794491714146 ✔ | 返回动作 |
| 对照：输入后等 0.6 s 再返回 | 33 ms（但此前已停 0.6 s） | 1794491567526–1794491567559 | 1794491567312（早于 T1） | 500ms 防抖 |

最后一行是对照：停够时间后，落盘发生在返回**之前**，来自防抖。它证明两种路径都会写，且内容一致。

**全部 6 个关键窗口都在 500 ms 以内（34–62 ms）**，满足任务要求；没有出现「达不到 500 ms 就冒称覆盖」的情况。

## 2. 逐项结果

### 检查一：新建笔记，最后输入后 46 ms 返回

- 步骤：列表页 `+` → 输入标题 `T1-title` → 正文 `para-one`、空行、`para-two` → 末字符逐字 `Z`/`E`/`T`/`A` → **46 ms 后点编辑页返回箭头**。
- 三方核对：
  - 列表：`共 1 条`，标题 `T1-title`，`今天 13:50`（`screenshots/03-list-after-new-back.png`）。
  - 重开：标题 `T1-title`、正文 `parae\n\nparatwoZETA`（`ui-dump/03-reopen-after-new.xml`）。
  - 持久化：`notes.json` 的 `title`/`content` 与重开完全一致（`notes/01-after-new-note-back.json`）。
- 结论：**未丢失末尾输入**，也没有多出空块或额外换行。新建笔记没有因「看起来是空的」被误删（`onBack` 的丢弃条件读的是落盘后的 `current`）。

### 检查二：已有笔记，改标题 + 删一段 + 追加末尾，34 ms 返回

- 步骤：打开该笔记 → 标题追加 `v2` → 光标移到正文末尾 → 退格 13 次删掉第二段 `paratwoZETA`（正文只剩 `parae`）→ 追加 `T`/`AI`/`L` → **34 ms 后点返回**。
- 三方核对：
  - 列表：`T1-titlev2`，`今天 13:51`。
  - 重开：标题 `T1-titlev2`，正文 `paraeTAIL`。
  - 持久化：`notes/02-after-edit-back.json` → `'T1-titlev2'` / `'paraeTAIL'`。
- 结论：**删除没有回滚成旧内容**（若存在旧快照回写，会看到 `paratwoZETA` 复活），末尾追加也没有丢。

### 检查三：键盘显示时的系统返回

| 动作 | 观测 | 结论 |
|---|---|---|
| 正文聚焦，键盘显示（`mInputShown=true`）后按**第一次**系统返回 | `mInputShown=false`，仍在编辑页（2 个 EditText 仍是 `T1-titlev2` / `paraeTAIL`） | **只收键盘**，标准 Android 行为，应用没有抢这次返回 |
| 再按**第二次**返回 | 离开编辑页，回列表（`共 1 条`），EditText 只剩列表页搜索框 | 正常退出，内容未变 |
| 键盘显示时**连续两次**返回（间隔 60 ms） | 直接回到列表（`共 2 条`），`mInputShown=false` | **不需要第三次**，没有吞键 |
| 键盘显示时点页面内返回箭头 | 直接离开编辑页并落盘 | 正常 |

- 没有出现「必须多按一次」或「返回后仍停在编辑页」。
- `ui-dump/06-sysback1-keyboard-hidden.xml`、`ui-dump/07-sysback2-left-editor.xml`、`ui-dump/09-double-back-list.xml`。

### 检查四：三次「修改 → 返回 → 重开」

| 轮次 | 最后输入→返回 | 持久化 `content` | 列表 | 重开后 |

## 3. 未做的与做不到的（如实登记）

- **未修改源码**：`ux/daily-ux-3` 工作区 `git status` 干净，`HEAD == 04f400f`，与基线 `git diff --stat` 为空。
- **未跑测试**：没有源码改动，按任务口径不重跑既有 9 / 87 套件；也没有新增测试（没有可测的行为变化）。
- **UI 自动化仍受限**：Espresso 3.5.1 在 API 37 的 `InputManager.getInstance()` 反射问题未变，本轮仍用手工操作 + `uiautomator dump` + 截图；未升级依赖绕过。
- **帧级回闪只做到抽样**：`screenrecord` 在本次模拟器上每次只录到 1.2–1.6 s 就自行结束（`moov atom not found` / 时长不足），拿不到可用视频；改用 `screencap` 连拍，采样间隔约 200–220 ms，**不能排除 1–2 帧的瞬态**。
- **注入通道的丢字**：`adb shell input text "para-one"` 实际落成 `parae`（丢了 `-on`），`"second"` 落成 `seond`。这是注入太快导致的丢键，不是应用行为——同一内容分两次输入即完整，且「屏幕上是什么」与「落盘是什么」始终逐字符一致（见 §2 三方核对）。证据里的正文因此是 `parae` / `paratwo` / `seond` 这种形状，不是拼写错误。
- **未验证**：真机、第三方输入法、中文输入法组词态（composing）下返回、深色主题、横屏、大字体、分屏/悬浮窗、TalkBack。
- **清理动作披露**：检查开始前对模拟器做过 2 次 `pm clear`（第一次后因注入丢字重来），此后所有检查**未再清数据**；未使用强杀、卸载作为验证手段。
