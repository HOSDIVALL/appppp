3. 尝试为 UI 行为补 androidTest（失败，已撤回）
----------------------------------------------------------------
思路：新增 NotesListActionsTest.kt（androidTest + createComposeRule），
      用 Compose 语义树断言"每行有更多入口 / 触控区 ≥48dp / 点击不打开笔记"。
命令：./gradlew assembleDebug assembleDebugAndroidTest
结果：测试 APK 编译打包成功（BUILD SUCCESSFUL in 40s，见
      logs/build-with-test.log），仅有 createComposeRule 的 v2 API 弃用警告。
安装：adb install -r（app 与 test APK），保留应用数据。
执行：adb shell am instrument -w -r \
        -e class com.example.myapplicationfirstapp.ui.NotesListActionsTest \
        com.example.myapplicationfirstapp.test/androidx.test.runner.AndroidJUnitRunner
日志：logs/instrument-NotesListActionsTest.txt
结果：Tests run: 7, Failures: 7，全部 Error，无一进入断言体。

失败根因（不是本改动引入，也不是测试代码写错）
  测试规则初始化阶段就崩：
    AndroidComposeTestRule$apply$1.evaluate
      -> androidx.compose.ui.test.EspressoLink.runUntilIdle
        -> androidx.test.espresso.Espresso.onIdle
          -> java.lang.NoSuchMethodException:
             android.hardware.input.InputManager.getInstance []
  即 espresso-core 3.5.1 通过反射调用 InputManager.getInstance()，
  该方法在 API 31+ 已不可反射访问，API 37 上直接抛异常。
  7 个用例（含一个只读写沙箱 JSON、不做任何 UI 交互的用例）全部在
  规则初始化时失败，证明失败点与断言无关。

处置：任务明确禁止新增/升级依赖、禁止改 Gradle，故不升级 espresso。
      该 androidTest 文件已删除（git status 干净，未进入任何提交），
      UI 行为改由"模拟器实测 + 层级/截图"覆盖。
      这条记录保留下来，是为了说明"为什么没有 Compose UI 测试"，
      而不是把 7 个 Error 当成 7 个通过。
