## 3. 原因

编辑页在「文字块获得焦点」和「键盘高度变化」时，调的是整块的 `BringIntoViewRequester.bringIntoView()`（无参版本）。当文字块比键盘弹出后的可视区还高时，这个请求只能按块的边界对齐：

- 一种情况把块顶对齐到视口顶部（A-3b：视图跳到第 01 行）；
- 另一种情况在键盘 inset 动画期间没有产生有效滚动（A-3：视图不动，光标留在键盘下方）。

两种情况的结果一样：**光标与正在输入的那一行在可视区之外**。

## 4. 修复（一处，`NoteEditorScreen.kt`，+29 / −3）

`rememberEditorFocusVisibility` 增加可选参数 `cursorRect: () -> Rect?`：

- 传了，就只请求「光标所在行」的矩形：`TextLayoutResult.getCursorRect(selection.end)`；
- 没传（标题栏、清单行这些单行输入框），仍走原来的整块请求，行为不变。

`EditableBlock` 用 `onTextLayout` 把最近一次布局存进一个普通数组（不是 `mutableStateOf`，避免每次布局触发重组），在请求时换算光标矩形。

没有加延时重试、没有循环请求、没有「每次重组都滚到底」。

## 6. 注入现象登记（不归因）

`adb shell input text` 偶尔吞字符：`ux4-43` 实际落成 `ux4-3`，`ux4-47` 落成 `ux47`。
这是注入口径的问题（发送过快），**未归因为应用行为**，也未据此做任何判断；对照用的都是判据量（光标矩形、键盘边界），不是字符是否完整。
